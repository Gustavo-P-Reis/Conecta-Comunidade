6. TESTES DE PERMISSÃO NO BANCO (AVANÇADO, OPCIONAL)
=====================================================================
Cada bloco roda numa única transação DESFEITA de propósito: nada é gravado. O
resultado aparece na mensagem de erro final ("RESULTADO -> ..."). Antes, pegue ids:
  select id, name from public.profiles limit 5;          -- <UUID-USUARIO>
  select id, user_id, title from public.events limit 5;  -- <ID-DO-EVENTO>, <UUID-DO-DONO>

6.1  UPDATE do vídeo pelo DONO do evento (testa o GRANT por coluna)
     Esperado: PERMITIDO (linhas afetadas: 1). "permission denied" = o grant da 003
     não foi aplicado.

  do $$
  declare v_n integer; v_resultado text;
  begin
    set local role authenticated;
    perform set_config('request.jwt.claim.sub', '<UUID-DO-DONO>', true);
    perform set_config('request.jwt.claims',
      '{"sub":"<UUID-DO-DONO>","role":"authenticated"}', true);
    begin
      update public.events set youtube_video_id = 'dQw4w9WgXcQ'
       where id = '<ID-DO-EVENTO>';
      get diagnostics v_n = row_count;
      v_resultado := 'PERMITIDO (linhas afetadas: ' || v_n || ')';
    exception when others then
      v_resultado := 'RECUSADO: ' || sqlerrm;
    end;
    raise exception 'RESULTADO -> UPDATE de youtube_video_id: %', v_resultado;
  end
  $$;

6.2  A restrição (CHECK) do ID
     Esperado: ID curto RECUSADO; ID válido ACEITO; NULL ACEITO.

  do $$
  declare v_a text; v_b text; v_c text;
  begin
    begin
      update public.events set youtube_video_id = 'curto' where id = '<ID-DO-EVENTO>';
      v_a := 'ACEITO (INESPERADO)';
    exception when check_violation then v_a := 'RECUSADO (esperado)'; end;
    begin
      update public.events set youtube_video_id = 'dQw4w9WgXcQ' where id = '<ID-DO-EVENTO>';
      v_b := 'ACEITO (esperado)';
    exception when check_violation then v_b := 'RECUSADO (INESPERADO)'; end;
    begin
      update public.events set youtube_video_id = null where id = '<ID-DO-EVENTO>';
      v_c := 'ACEITO (esperado)';
    exception when check_violation then v_c := 'RECUSADO (INESPERADO)'; end;
    raise exception 'RESULTADO -> ID curto: % | ID válido: % | NULL: %', v_a, v_b, v_c;
  end
  $$;

9. DECISÕES TÉCNICAS E LIMITES
=====================================================================
 - Guarda só o ID (11 caracteres) em events.youtube_video_id: nenhuma URL arbitrária
   fica no banco, e só o ID validado entra na URL do player.
 - Extração por URL() com lista exata de hosts (youtube.com, www/m.youtube.com,
   youtu.be, youtube-nocookie.com): domínios parecidos, usuário/senha/porta e
   esquemas como javascript: são recusados. Formatos aceitos: watch?v=, youtu.be/,
   /embed/, /shorts/, /live/, /v/. Todos os outros parâmetros do link são
   descartados. Links de music.youtube.com e IDs soltos (sem link) NÃO são aceitos.
 - A mesma função valida no formulário (Zod), na Server Action (autoritativa), na
   página do evento (defesa em profundidade) e o CHECK do banco repete o padrão.
 - Edição: o formulário só envia video_url quando o campo mudou. No servidor,
   ausente = não mexe; vazio = remove (NULL); link válido = atualiza o ID.
 - Player: iframe em youtube-nocookie.com, loading="lazy",
   referrerPolicy="strict-origin-when-cross-origin" (o YouTube exige o Referer; com
   no-referrer ocorre o erro 153), allow sem autoplay, sem sandbox, sem
   dangerouslySetInnerHTML. Sem vídeo, o componente não renderiza nada.
 - Vídeos privados, removidos, sem incorporação ou com restrição de idade não são
   detectados no servidor (não há API, chave nem oEmbed). O YouTube mostra a própria
   mensagem dentro do player, e o link "Assistir no YouTube" fica logo abaixo.
 - Shorts: aceitos; aparecem no player 16:9 com faixas laterais (confirme no teste).
 - Não há CSP no projeto. Se um dia houver, precisará de
   frame-src https://www.youtube-nocookie.com.
 - O iframe contata o YouTube/Google ao carregar; vale mencionar na documentação de
   privacidade do TCC.
 - Não foram alterados: dependências, autenticação, RLS existente, políticas,
   painel admin, gráficos, classificação regional, regra de data de eventos.
 - revalidatePath("/admin") não é necessário: o vídeo não aparece no painel.
